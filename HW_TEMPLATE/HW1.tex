\section{سوال ۳: \lr{Fork Bomb}}
\subsection{مفهوم \lr{Fork Bomb} و نحوه عملکرد آن}

\lr{Fork Bomb} یک نوع حمله \lr{Denial of Service} است که با ایجاد تعداد بسیار زیادی پردازه در مدت زمان کوتاه، منابع سیستم (یعنی CPU ، حافظه و جدول پردازه‌ها) را مصرف می‌کند و سیستم را غیرقابل استفاده می‌سازد.

نحوه عملکرد: \lr{Fork Bomb} معمولاً یک حلقه بی‌نهایت است که در هر تکرار، با استفاده از فراخوان سیستمی \lr{fork()}، یک کپی از خودش ایجاد می‌کند. هر پردازه جدید نیز همین کار را انجام می‌دهد، بنابراین تعداد پردازه‌ها به صورت نمایی رشد می‌کند. برای مثال، اگر در هر ثانیه هر پردازه یک پردازه جدید ایجاد کند، پس از ۱۰ ثانیه بیش از ۱۰۰۰ پردازه خواهیم داشت، و پس از ۲۰ ثانیه بیش از یک میلیون پردازه.

\subsection{نمونه \lr{Fork Bomb} ساده}

یک نمونه ساده \lr{Fork Bomb} در فایل \lr{fork\_bomb.c} پیاده‌سازی شده است:

\begin{LTR}
\begin{verbatim}
#include <unistd.h>
#include <stdio.h>
#include <sys/types.h>

int main() {
    while(1) {
        fork();
    }
    return 0;
}
\end{verbatim}
\end{LTR}
برای کامپایل و اجرا:
\begin{LTR}
\begin{verbatim}
gcc -o fork_bomb fork_bomb.c
./fork_bomb
\end{verbatim}
\end{LTR}

\subsection{اثرات Fork Bomb روی منابع سیستم}

برای تحلیل اثرات Fork Bomb روی منابع سیستم، می‌توان از دستورات زیر استفاده کرد:

\begin{LTR}
\begin{verbatim}
# View number of processes
ps aux | wc -l

# View CPU and memory usage
top
# or
htop

# View system limits
ulimit -a
\end{verbatim}
\end{LTR}

با کمک \lr{ctrl+c} این مشکل حل نمی‌شود زیرا این دستور برای استاپ کردن یک پراسس است اما \lr{fork\_bomb} تعداد خیلی زیادی پراسس ایجاد می‌کند که نمی‌توان به کمک این دستور آن‌ها را استاپ کرد.
\\
برای جلوگیری از این مشکل می‌توان از دستور \lr{ulimit -u 100} استفاده کرد تا برای fork های یوزر لیمیت گذاشت و نگذاریم که پراسس ها از یک تعدادی بیشتر شوند.

\subsection{راه‌های مقابله با Fork Bomb}

راه‌های مختلفی برای مقابله با Fork Bomb وجود دارد:

\begin{enumerate}
    \item \textbf{استفاده از ulimit}: می‌توان تعداد پردازه‌های مجاز برای یک کاربر را محدود کرد:
    \begin{LTR}
    \begin{verbatim}
    ulimit -u 100  # Limit to 100 processes
    \end{verbatim}
    \end{LTR}
    \item \textbf{استفاده از cgroups}: در سیستم‌های مدرن لینوکس، می‌توان از cgroups برای محدود کردن منابع استفاده کرد.
    
    \item \textbf{کشتن پردازه‌ها}: استفاده از \lr{pkill} یا \lr{killall} برای متوقف کردن تمام پردازه‌های Fork Bomb:
    \begin{LTR}
    \begin{verbatim}
    pkill -9 fork_bomb
    # or
    killall -9 fork_bomb
    \end{verbatim}
    \end{LTR}
    \item \textbf{استفاده از اسکریپت خودکار}: اسکریپت \lr{stop\_fork\_bomb.sh} برای این منظور تهیه شده است.
    
    \item \textbf{تنظیمات سیستم}: می‌توان در فایل \lr{/etc/security/limits.conf} محدودیت‌های دائمی تعریف کرد.
\end{enumerate}

\subsection{ابزار perf در لینوکس}

\lr{perf} یک ابزار قدرتمند برای تحلیل عملکرد در لینوکس است که امکان جمع‌آوری داده‌های عملکردی در سطح هسته سیستم‌عامل و سخت‌افزار را فراهم می‌سازد.

ویژگی‌های اصلی perf:
\begin{itemize}
    \item \textbf{نمونه‌برداری از CPU}: جمع‌آوری اطلاعات درباره توابعی که بیشترین زمان CPU را مصرف می‌کنند
    \item \textbf{تحلیل رویدادهای سخت‌افزاری}: دسترسی به \lr{Performance Monitoring Unit (PMU)} برای تحلیل \lr{cache misses}، \lr{branch mispredictions} و غیره
    \item \textbf{تحلیل \lr{call stack}}: امکان مشاهده زنجیره فراخوانی توابع
    \item \textbf{تحلیل زمان واقعی}: امکان مشاهده عملکرد برنامه در حین اجرا
\end{itemize}

دستورات مفید perf :
\begin{LTR}
\begin{verbatim}
# Record samples
perf record -g ./program

# Display report
perf report

# Interactive display
perf top

# Save output for FlameGraph
perf script > perf_script.out
\end{verbatim}
\end{LTR}

\subsection{FlameGraph}

\begin{itemize}

\end{itemize}
